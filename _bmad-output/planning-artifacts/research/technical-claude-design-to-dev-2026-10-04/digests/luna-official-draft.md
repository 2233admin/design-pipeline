# Claude 设计到前端交付：把原型反馈接到真实运行实现

**研究日期：** 2026-10-03  
**决策问题：** 在不混淆设计概念、Artifact/原型预览与目标应用实现的前提下，design-pipeline 最值得增强的一个闭环是什么？  
**主张：** 只增强一个目标——**可追溯的“设计快照→本地运行预览→元素级反馈→实现验收”交接回路**。交接时固定一份设计快照作为目标；本地运行目标实现，针对具体组件/视口/状态记录可复现的反馈；每次迭代把反馈回指到该设计快照与实现证据。不是复制 Claude Design，也不是再造评分/门禁体系。

## 执行摘要

Anthropic 的公开产品说明覆盖从设计产出、内联反馈/直接编辑到 Claude Code handoff 的路径；Claude Artifacts 帮助还说明了底层代码、版本切换和下载。但公开资料没有定义 handoff 包固定清单，也没有证明原型与目标仓库、当前实现、或生产运行时保持逐版本同步。[1][2][3] Anthropic 工程团队公开的前端实验将“真实运行页面的交互检查”与静态图评分区分，并把明确标准下的反馈送回生成器；其结果迭代不总是线性，说明局部反馈应可回看、可验证，而非盲目自动采纳。[4]

因此应把闭环的关键状态定义成：**设计版本（输入） + 运行目标（环境/提交） + 定位反馈（元素/状态/视口） + 验收证据（截图/交互结果）**。保持既有 gate 与 receipt lineage 的用法，不将 Component Conformance 等同 Visual Acceptance（后者看目标实际渲染，前者检查组件/契约符合性）。上述设计建议是对公开资料和本项目既有决策语境的推论，不是 Anthropic 声称的内置功能。

## 证据与边界

### 官方资料支持的能力

- Claude Design 是面向视觉设计、原型等产物的画布式工作流；官方称可用对话、内联评论、直接编辑、滑杆细化，并可读取团队设计系统来源；支持交付给 Claude Code 的 handoff bundle。[1]
- 官方 Artifact 帮助列举 HTML、SVG、图表及交互式 React 等产物，描述代码查看、复制/下载、版本选择和直接迭代；AI-powered Artifact 的应用运行在 Anthropic 基础设施上。已发布 Artifact 才支持持久存储，开发/测试阶段存储操作不成功。[2]
- Claude Design 帮助的索引内容描述 /design-sync 与 /design 对设计同步、从代码导入/生成 live prototype/构建实现的作用；公开资料没有说明 handoff bundle 的固定 manifest，因此不能假定其中必有某个源码/token 文件，也不能把“handoff”理解为验证完毕。[3]
- Anthropic 工程实验报告称：前端评估器使用 Playwright MCP 与运行页面交互、截图并按明确准则反馈；相较单张静态图，评估器能够检查真实交互。多轮改进不是保证单调，且后期复杂度可能增加。[4]

本任务提供的既有桌面观察，作为 **observed-data** 而非 Anthropic 能力证据：匿名化设计工作区以分栏画布展示，有组件静态预览与来源快照可能陈旧提示。只记录抽象体验，不保留项目名、仓库标识、私有路径、截图摘录或可识别细节。它提示一个一般性风险：设计系统呈现与导入来源时效可能脱节，但不能据此断言同步机制、自动更新行为或版本一致性语义。

## 单一增强目标

**设计快照绑定的本地反馈迭代**：一次任务选择一个不可歧义的设计/版本输入，并在该输入上实现；每条反馈具有组件或页面定位、状态/视口、明确预期与当前观察；反馈在目标应用实际运行态复现后才进入实现修订；输出把设计输入、实现目标和视觉/交互验收结果关联起来。

这是建议的流程增强，而非新增平行 gate、质量分数、遥测或自动修改系统。视觉验收与组件符合性继续分立：组件契约符合不证明视觉实现等同目标；视觉截图相似也不证明交互正确。

### 取舍与边界

- **取舍：** 比“截张图让模型看”成本略高（需启动真实目标、检查关键状态），换取发现交互/布局/状态差异；采用单个明确设计快照，换取版本归因能力，不承诺持续双向同步。
- **范围内：** 设计快照和来源标识、目标实现版本/运行方式、元素级局部反馈、关键交互观察、实施后视觉复核与交接记录。
- **范围外：** 仿建 Claude Design 的画布/分享/评论功能；依赖未知 handoff 内部格式；证明生产可用性或完整无障碍；自动批准主观设计；竞争产品比较；改动其他项目或披露私有观察。
- **依据：** 公开官方材料明确支持前端原型与反馈/交接，但 handoff 的底层一致性契约未知；运行态评估的价值有 Anthropic 工程实验支持。[1][3][4]

### 验收场景（供后续实现验证）

1. **版本归因：** 设计迭代 A 交接实现后再产生 B；报告/验收仍可识别实现目标对应的是 A 还是 B，不把“最新版”默认为实际输入。
2. **局部反馈闭环：** 对一个具体组件在明确视口和交互状态提出偏差；修改后在相同目标运行环境和状态复验，能够确认结果或记录未通过/未复现。
3. **静态与运行态分离：** 静态截图通过但点击/展开行为错误时，视觉截图不能代替交互验收；Artifact/独立原型的运行结果不能被标记为目标应用验收。
4. **来源过期提示：** 设计系统来源快照疑似 stale 时，交接明确标示基于哪个已记录来源状态；不声称自动同步或最新。
5. **可交付证据：** 结束产物能将设计输入、目标代码/运行标识、局部问题及修复后证据关联；组件符合性结果与视觉接受结果分别陈述。
