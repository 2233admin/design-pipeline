- (decision) 本轮交付是 feature altitude 的 Architecture spine，目标是 build-substrate；不扩写实现说明，不生成展示 deck。
- (decision) 整体范式采用 invariant-first 的分层管线与 ports-and-adapters 边界：摄取、规范化本地产物、治理、适应性路由、工具链、执行与证据；依赖只向后续层流动。
- (constraint) 运行时是本地 Skill + CLI + 文件系统，不是 MCP 服务；架构不得引入远端服务运行时或隐式 MCP 依赖。
- (constraint) Methodology Kernel 是稳定质量边界；Adaptive Orchestration、Dynamic Capability Discovery、User Collaboration Skill、Project Adaptation Skill 只能选择和编排，不能改写 Kernel 或绕过项目约束。
- (decision) DesignMD 资源先作为带来源、哈希、许可与状态的本地规范化目录；默认 reference-only，不自动 hydrate、安装、执行或把远端代码变成运行时依赖。
- (decision) DesignMD 同步通过 HTML、sitemap、llms/llms-full 发现，受 robots.txt、页数/并发/超时/大小边界约束；阻断或部分失败必须可见，不能伪装成完整成功。
- (decision) 目录发布采用原子替换并保留 last-known-good；持久化 contentPath 必须项目相对且通过 containment 校验，不能越界或经符号链接逃逸。
- (decision) 设计工具接入采用本地导出优先的 provider-neutral receipt：输入文件哈希、映射、可编辑性、证据与来源；首个实现顺序为 Figma JSON/SVG/PNG/tokens，Penpot 复用同一契约，均不做 API、登录或写回。
- (decision) 路由图每次只能有一个 primary route；显式能力/关键词路由优先于泛化路由；review、blocked、licensed 或未验证能力必须向工具链和执行层传播，不能降级成 ready。
- (constraint) route、toolchain、execution 之间用 owner、route id 与输入哈希绑定；执行只能消费已解析且通过治理的计划，并输出可审计证据。
- (decision) 上下文优先级为 task > project > user > defaults；用户建模只保留有限、可审计、影子模式的协作偏好，不保存原始对话、秘密、敏感推断或人格标签，且不得覆盖 gates。
- (decision) 状态所有权分离：源快照不可变，适应性账本负责持久策略，路由计划负责 primary 与哈希绑定，执行层负责生命周期和证据；跨层写入必须经过明确事件。
- (decision) 错误与结果使用版本化 JSON envelope 和稳定 exit code，至少区分 ready、invalid、blocked、review、fidelity-mismatch；JSON 采用确定性序列化和 SHA-256。
- (constraint) 支持 Node 22+；Python 仅由 BMAD 技能通过 uv 运行，当前不新增运行时依赖；所有新能力必须能在本地离线测试。
- (question) 用户画像的持久化、查看与遗忘是否在 v1 直接落地，还是由后续独立 epic 交付；当前架构只固定安全边界和优先级，不承诺完整画像产品。
- (question) Figma/Penpot 各类导出的精确字段映射与保真度门槛应在 bmad-spec 和 stories 中逐项冻结。
