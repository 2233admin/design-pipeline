- (note) 需求来源为 _bmad-output/planning-artifacts/prds/prd-design-pipeline-2026-08-23/prd.md；架构约束来源为 _bmad-output/planning-artifacts/architecture/architecture-design-pipeline-2026-08-23/ARCHITECTURE-SPINE.md；项目上下文为 CONTEXT.md。
- (capability) CAP-1｜资源源同步：维护者可以同步 DesignMD 的可发现一方资源并得到稳定分类、来源、内容和状态；成功条件是五类条目可搜索/inspect，边界、重试、去重和 URL 级错误可验证。
- (capability) CAP-2｜来源与准入验证：系统可以把资源来源、许可、安全、内容 hash 和 admission 状态绑定到本地条目；成功条件是未知或不安全资源保持 reference-only/review/blocked，不能成为默认实现权威。
- (capability) CAP-3｜本地设计工具输入：用户可以提交声明支持的 Figma、Penpot 或通用本地导出物；成功条件是输入经过根目录、格式、文件和字节 hash 校验并生成 provider-neutral receipt，不能把 receipt validator 当作 importer 完成。
- (capability) CAP-4｜设计工件归一化：系统可以把资源和工具输入映射为带来源、语义角色、tokens/style、映射、可编辑性和 fidelity/loss 的 Design Artifact；成功条件是缺失语义显式记录，provider 原始模型不泄漏到路由层。
- (capability) CAP-5｜能力探测与 readiness：系统可以只读探测工具/能力的版本、可用性、输入模式、生命周期和 fallback；成功条件是只有具备证据的真实 executable lifecycle 才能标记 ready，agent-owned/manual/reference-only 使用非 ready 状态。
- (capability) CAP-6｜路由与 Skill→CLI→toolchain 交接：Agent 可以依据需求、项目和准入上下文选择唯一 primary route；成功条件是 routeId、owner、输入/资源 hash、plan hash 全链路绑定，漂移或 blocked 状态拒绝执行。
- (capability) CAP-7｜用户/项目上下文协作：系统可以使用 task、project、user、defaults 四层有限上下文改善选择和交接；成功条件是 task > project > user > defaults，数据可审计且 shadow-only，不保存原始对话/秘密/敏感画像，不能覆盖 Kernel 或 gates。
- (capability) CAP-8｜快照维护与恢复：系统可以重复同步并识别 added、changed、disappeared、failed、stale，失败时保留 last-known-good；成功条件是 diff receipt、前后 snapshot hash、错误原因和下一动作可验证，全失败也输出稳定 recovery envelope。
- (constraint) 产品是本地优先 Skill + CLI + 文件系统，不是 MCP 服务；网络只作为可选读取输入，不能成为执行运行时依赖。
- (constraint) 远程 HTML、Markdown、prompt、脚本、命令、npm 包和插件内容默认 inert；不自动 hydrate、安装、执行或绕过许可证与服务条款。
- (constraint) 外部抓取必须有 robots、公开目标/重定向校验、凭据和敏感 query 过滤、响应大小/页数/并发/超时/重试上限；策略不可用时 blocked 或 partial，不能静默放行。
- (constraint) 所有 catalog contentPath、artifact、evidence 路径必须声明基准并通过 realpath containment，拒绝 traversal、绝对路径、symlink/junction escape 和非文件目标。
- (constraint) 快照候选先验证后原子发布；失败保留上一份有效快照。JSON envelope、hash、排序、时间戳和 domain-status/exit-class 映射必须确定性且版本化。
- (constraint) ready 只表示存在经测试的可执行生命周期；review、blocked、invalid、fidelity-mismatch、agent-owned、manual、reference-only 不能隐式降级或升级。
- (constraint) 上下文优先级固定为 task > project > user > defaults；Methodology Kernel、项目约束、许可证和安全 gates 不可被个性化或适应策略覆盖。
- (constraint) 支持 Node.js 22+；Python 只由 BMAD 技能通过 uv 运行；v1 不做 Figma/Penpot/API 登录、远端写回、后台调度或云端同步。
- (assumption) v1 的 DesignMD 完整性定义为完整发现一方目录页面并保留受治理的外部引用，不递归抓取每个外部工具供应商。
- (assumption) Figma/Penpot 先走 local-file 或受控 plugin-export/安全本地 archive 的 export-first 路线，具体 provider 输入格式需要在本 Spec 的 open questions 中冻结。
- (assumption) 当前代码的 receipt、路由、原子快照和部分 handoff 校验是 brownfield 基线，但安全抓取、完整 importer、全链路 source hash 和 ready lifecycle 仍是待交付实现。
- (question) Figma JSON/tokens 的合法 v1 source mode 是 local-file、controlled-plugin-export，还是另行允许 API-export；Penpot 是否只接受导出资产还是安全 .penpot archive？
- (question) response-byte cap、lock timeout、retention 和 retry budget 的默认数值定为多少，哪些可以按 source 配置？
- (question) 公共 CLI 的 domain status 与 process exit class 的最终映射表和兼容旧命令的迁移策略是什么？
- (question) agent-owned/manual route 的 Skill action、evidence checkpoint 和用户确认边界如何定义，才能既可用又不冒充 executable ready？
- (question) DesignMD diff receipt 的 revision、disappeared/stale 保留期限和 route admission 阻断规则是否按资源 kind 区分？
