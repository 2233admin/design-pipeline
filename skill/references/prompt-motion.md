skills, not one installable library. Select a case because it answers the current product or
motion question. User references and the product's actual identity take priority. Ordinary UI or
CSS work does not become a film task because a case looks useful.

## Adopt through the existing reference flow

1. In the task's `reference.md`, record the exact case URL, author, original repository, review
   date, role (method discovery, visual direction, edit or sound), product relevance and access
   result. Separate **observed**, **inferred/proposed** and **unknown** statements.
2. A page-only read is method discovery. Record `Observed time ranges: none; video not watched;
   audio not heard`. It cannot complete moving-reference observation or justify a copied shot.
3. When legitimately supplied local media is available, retain its original bytes and use
   `reference analyze-video` with the existing [reference-spec.md](reference-spec.md). Inspect
   ordered local frames; record source times/frame ids and actual hearing limits. Adopt their
   existing report digest through `reference-evidence.json`, without creating another receipt.
4. Keep the proposed transfer separate: identify the actual product assets/components, preserved
   invariants, selected engine and unresolved evidence. Bind applicable maintained method paths
   as ordinary task inputs or visual guides so existing hash invalidation remains effective.

HTML video keeps the existing HyperFrames route; an example's Remotion tag, frame rate or style
does not override the project. Repository source readability, a callable method and a verified
maintenance tool are different claims. Other site entries are discovery candidates only; this
round does not import session-story, buildfast-skills or any further libraries.
