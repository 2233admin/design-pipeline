# Entitlements

ATAS tier gating 的对应，做成**许可与权限**：按计划（plan）、角色（role）、数据源（data）三类来源决定功能可用与配额——每图指标数、活跃连接数、资产数、Heatmap / Big Trades 历史天数、MBO、期权流、实盘下单、限额写入等。GPL 自部署默认全开；托管或团队部署由部署者配置。它同时是机构级 RBAC（PM / Trader / Quant / Risk / Ops / Compliance）与四眼原则的落点。

## 结构

- 左：计划与角色列表；右：能力 × 计划矩阵，每格标来源（PLAN / ROLE / DATA）。
- 四页：功能、配额、数据源（哪个适配器提供什么深度）、审计（谁改了门控）。
- 被门控的功能在各面板里**灰显并说明来源**（"需要 L2 录制适配器" / "Guest 角色只读"），不隐藏、不伪装成不存在。

## 交互

- 改门控 = 命令 `entitlement.set` + 确认 + 审计行；角色切换走 StatusBar 账户段。
- 配额临近时相关面板显示 Meter（如"指标 5 / 6"）。
- 数据源来源的门控自动随 DataSources 状态变化，不手工维护。

## 规则

- 门控只影响**入口与配额**，不改变数据与盈亏口径。
- 任何门控都能被部署者关闭；代码里没有写死的上限。
- 数据源门控是事实（适配器声明），计划 / 角色门控是策略（配置）；两者在矩阵里分开标。

## 谁提供什么

- 组件：plans[]、roles[]、matrix{}、sources{}。
- 后端：权限服务（角色、计划）、适配器声明（数据深度）、审计。

## ATAS 对照

承接 tier gating（指标 / 连接 / 资产 / 历史天数、MBO / Options / Risk Manager 资产数、Cross-Trading）。原则：能力 1:1——有门控机制；操作我们的——部署者配置、默认全开、来源可见。
