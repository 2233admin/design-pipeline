# SymbolMap

代码映射：同一品种在各数据源 / 柜台的代码对照，规范码（交易所码 + 后缀）为主键。回答"这四个源说的是不是同一只票"。冲突（源之间不一致）与缺失（源里没有）要人确认；确认是写命令。GO Bar 的粘贴识别和 Profile 的 `symbolFormat` 都靠它。

## 结构

- 顶行：品种数与源数 · 视图 Segmented（冲突 / 缺失 / 全部）· 规范码规则说明。
- 列：灯（ok 一致 / warn 冲突 / off 有缺失）· 规范码 + 名称 · 各源代码（一致 `ink-200`，不一致 amber ≠，缺 `ink-400`）· 动作（确认 / 补）。
- 源列数随接入源变化（≤ 6 列，更多横滚）。

## 交互

- 「确认」→ 弹选择：哪个源的码是对的（或手填），写 `symbolmap.resolve` 命令（走确认框——它影响所有下游）。
- 「补」→ 向数据平台提交查找任务。
- 搜索：任意源的码或名称 / 拼音。
- 点击规范码 → LinkContext。

## 规则

- 映射表权威在数据平台；前端只能确认冲突和手填缺失，不能改规范码规则。
- 退市 / 更名的历史映射保留（带生效区间），回测用 point-in-time 映射。
- 不自动"猜"映射；猜测由数据平台任务产生并标 `建议`，人确认才生效。

## 谁提供什么

- 组件：rows[]（canonical、name、bySource{}、state）、sources[]、filter、onResolve、onLookup。
- 调用方：数据平台映射表（Query）。
