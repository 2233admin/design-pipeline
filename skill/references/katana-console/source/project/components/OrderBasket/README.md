# OrderBasket

篓子单：一组跨账户订单作为一个整体来预检、排序、拆批、提交。入口是 RebalanceDesk（也可从 PositionBook 多选「平仓」或 Screener 多选「等权买入」生成）。它是 OrderTicket 的多行版本，同样是**核心界面**：结构不可皮肤化，每一批提交都走确认框。

## 结构

- 顶行下方一块 ConsensusBlock（整篓三方表决，当前批）。
- 顶行：篓子 id 与来源 · 拆批 Segmented（一次 / n 批·间隔 / TWAP 窗口，≤ 3）· 顺序（先卖后买 / 按账户 / 自定义）· 右侧预检灯计数（ok / warn / danger）。
- 列：预检灯 · 账户短码 · 代码·名称 · 方向（订单流色）· 数量 · 限价 · 批次（点阵标；当前批 orange，已成 `ink-300`）· 预检说明（≤ 20 字符：可卖 ✓ · 风控 ✓ / 涨停价 · 可能不成 / 资金不足）。
- 用户移除的行保留为「跳过」`ink-300`，篓子记录完整。
- 页脚：批次进度（点阵格，当前批橙纹理）· 净现金变化 · 剩余笔数与待确认数 · **提交当前批 → 确认（n 笔）**。

## 交互

- 提交一批 → 一个确认框列出该批全部订单（账户、方向、数量、限价、hash）；确认后进 OrderBlotter，篓子里这些行变 `B1 已成 / 部分`。
- 下一批在间隔到达后变「待确认」并亮描边，不会自动发；间隔到了人不在，篓子停住，不超时失效。
- 行内：改数量 / 限价（LCD 输入）、改账户、移除；任何改动使该批 hash 变、待确认状态重置。
- 顺序拖动：行拖拽换批（弹簧让位）。
- 全部完成：页脚变「完成 · 成交 n/m · 滑点 x」，`fill` 音效一次（不是每笔），不做庆祝动效。

## 规则

- danger 预检（资金不足、风控拒绝、停牌）的行不能提交，必须移除或修正。
- 市场规则（整手、起点数量、涨跌停、T+1 可卖）由 Profile 预检给出文字，组件不算。
- 篓子是账户服务的一等对象（有 id、可恢复）；刷新页面后从 Query 恢复进度。
- 实盘账户所在的篓子顶行带 amber `LIVE` 点阵标。
- 不做"一键全发"；拆批最少 1 批最多 10 批。

## 谁提供什么

- 组件：basket（id、source、orders[]、split、order、batches[]）、precheck（执行网关）、onSubmitBatch(batchId) → 命令。
- 调用方：执行网关预检与状态流、Profile、账户服务（篓子持久化）。
