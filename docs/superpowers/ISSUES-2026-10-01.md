## 三个根因

### 根因 1：不认识"已有项目"

在已有项目里，工具不会把 agent 引到项目自己的规则和检查上。

- `ui` 的 work 一步只有一句"去读 `pipeline-reference.md`"（`workflow-core.cjs:42-45`）。那份文档 92KB，没有定义三档，对已有项目只有零星几行。（实测）
- 不提示规则文件（AGENTS.md/CLAUDE.md/CONTEXT.md/docs）、不提示 `package.json` 里的检查命令。（实测）
- `route` 认不出普通的改动任务（score 0、low），却仍报 ready，然后引到 foundation/prism；`foundation check` 在 Vite 项目里退出码 2。（实测）
- 栈登记表不认 material-web、css-modules、styled-components、angular，参考文档还写着"栈判定不 ready 就停"（`frontend-stack-core.cjs:9`、`pipeline-reference.md:930`）。（实测）
- `next` 说不用 OpenSpec，参考文档 :26、:50 说要用；quick 不要 DESIGN.md，参考文档 :89 说要。（读代码）

**归属**：`add-existing-project-intake`（待你选方案）。

### 根因 2：完成条件可以伪造，或者已经过期

- `decide --stage deliver` 不给 `--answer` 也算完成（`workflow-core.cjs:125`）。（实测）
- 评审和交付可以提前回答，`next` 走到 done 时一次都不问人（D1）。（实测，部分 gate 合成）
- 删掉输入文件仍算新鲜（D5）；只看修改时间不看内容（D4）；换了草稿，旧的 accept 仍然有效（D2）；被拒的草稿不改也能再送审（D11）。（实测，部分 gate 合成）
- 检查报 passed 但结果没记下来（D13）。（实测）
- `decide intake` 会覆盖用户已有的 `brief.md`。（实测）
- D1–D15 全部属实；另有 `--choice banana` 被接受、已有项目再传 `--tier` 被忽略等小问题。
- 现有测试把这些行为锁成了预期：`tests/workflow-next.test.cjs:58,140,365` 等。

**归属**：`align-workflow-lifecycle`（S0 起）。

### 根因 3：`web` 写死根目录 `index.html`

- 有 `index.html` 就算构建完成（`web.cjs:53`）：Vite 项目直接跳过构建，`b631fcd` 的 treatment 和 section brief 不会出现。（实测）
- 没有 `index.html` 的项目（例如 Next.js）会被要求另建一个独立页面。（实测）
- 判断新鲜只看 `interaction.json` 和 `index.html`（`web.cjs:69`），改了 `src/` 不会重新检查。（实测，gate 合成）
- 页面检查用 `file://` 打开 Vite 页面是空白，报错说成选择器问题；还会让 agent 往项目里装 `puppeteer-core`。（实测）
- 评审提示要看三种尺寸的截图和 `qa.md`，但没有任何步骤产出它们（D15）。

**归属**：`align-workflow-lifecycle`（web 相关切片）+ `add-web-composition-checks`。

## 能力缺口（头脑风暴结论，2026-10-01）

两个讨论 agent（一个往外发散、一个保守挑刺）各自只读查了代码和 KATANAview 的文档，结论基本一致。凡是工程上已有成熟做法的，直接用，不自己发明。

### 总判断

- KATANAview 自己已有一套搬功能的流程：
  - `docs/ux/ATAS_CAPTURE_PROTOCOL.md`：逐控件截图、录屏、三句话；
  - `ATAS_COMPATIBILITY_MATRIX.md`：功能对照表；
  - `ORDERFLOW_ACCEPTANCE_GATES.md`：五道验收门；
  - `UX_DECISION_LEDGER.md`：决策记录。

  它缺的是浏览器里的检查和基准截图（Gate B 写明"真实浏览器截图不存在"）。
- 所以工具在已有项目里应当**补宿主流程的缺口**，而不是在旁边再跑一套。作废那轮试跑里的线索也指向这一点（只是线索）：点名 skill 的两次都在走工具流程，0 改动；没用 skill 的那次读了 `CONTEXT.md`，改了文件，也跑了测试。
