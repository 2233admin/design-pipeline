## `tunables.json`

```json
{
  "schema": "design-pipeline.tunables.v1",
  "params": [
    { "id": "title-text", "label": "Title", "group": "hero", "type": "text", "default": "Ship it", "window": { "startSec": 0.5, "endSec": 3 } },
    { "id": "accent", "label": "Accent colour", "group": "brand", "type": "color", "default": "#ff5a36" },
    { "id": "card-radius", "label": "Card radius", "group": "cards", "type": "range", "min": 0, "max": 32, "step": 1, "unit": "px", "default": 12 },
    { "id": "beat-02-duration", "label": "Beat 2 length", "group": "timing", "type": "range", "min": 0.4, "max": 3, "step": 0.1, "unit": "s", "default": 1.2 },
    { "id": "entrance-ease", "label": "Entrance ease", "group": "timing", "type": "select", "options": ["power2.out", "expo.out", "back.out(1.4)"], "default": "power2.out" },
    { "id": "grain", "label": "Film grain", "group": "look", "type": "checkbox", "default": true }
  ],
  "values": { "accent": "#00c2a8", "beat-02-duration": 1.6 }
}
```

- A param is a Playground control: `id` (lowercase letters, digits, hyphens), `label`, `group`, `type`
  (`range`, `select`, `checkbox`, `color`, `text`), `default`; `range` also has `min`, `max`, `step`
  (`min < max`, `step > 0`); `select` has 2 or more distinct `options`. `assertControl` enforces
  these, so a Playground and a tunables file agree on what a control is.
- Added by tunables: `unit` (a label; the CSS units `px rem em % s ms deg vw vh` are also appended
  to the CSS custom property), `window` (`{ startSec, endSec }`, `0 <= startSec < endSec`; where the
  param shows), `dynamic` (true when the project builds the id at run time, so the static read check
  skips it).
- Rules on top: `color` is `#rrggbb` or `#rrggbbaa` (lower-cased on write); `text` is at most 500
  characters with no control characters; ids are unique.
- `values` holds only declared ids, each valid for its param. Effective value: `values[id]` if
  present, else `default`. No runtime name appears in the file.

The contract and the values are in one file because a person edits one file. `set` and `reset`
change only `values`; adding, removing or changing a param is a change to the page or film and is
made by whoever builds it.

## `tunables.js`

`sync` rewrites it from the effective values; it is deterministic (ids sorted, no clock):

```js
// generated by designer-pipeline tunables sync; do not edit. digest sha256:<hex of the effective values>
(function () {
  var v = {"accent":"#00c2a8","beat-02-duration":1.6,"card-radius":12,"grain":true,"title-text":"Ship it"};
  window.tunable = function (id) {
    if (!Object.prototype.hasOwnProperty.call(v, id)) throw new Error("undeclared tunable: " + id);
    return v[id];
  };
  var root = document.documentElement, s = root.style;
  s.setProperty("--tn-accent", "#00c2a8");
  s.setProperty("--tn-beat-02-duration", "1.6s");
  s.setProperty("--tn-card-radius", "12px");
  root.setAttribute("data-tn-grain", "true");
  root.setAttribute("data-tn-entrance-ease", "power2.out");
  function text() {
    var n = document.querySelectorAll("[data-tn-text]");
    for (var i = 0; i < n.length; i++) { var k = n[i].getAttribute("data-tn-text"); if (k in v) n[i].textContent = v[k]; }
  }
  if (document.readyState === "loading") document.addEventListener("DOMContentLoaded", text); else text();
})();
```

| Param type | In script | In CSS or HTML |
| --- | --- | --- |
| `range` | `tunable("id")` (a number) | `var(--tn-id)`, with its unit when it is a CSS unit |
| `color` | `tunable("id")` | `var(--tn-id)` |
| `select`, `checkbox` | `tunable("id")` | `[data-tn-id="value"]` on `<html>`; a checkbox is `"true"` or `"false"` |
| `text` | `tunable("id")` | `<h1 data-tn-text="id">` |

- It reads no `location`, storage, clock or random source, so it keeps the determinism rules in
  `hyperframes.md`. A test scans the generator's code (values removed) for those words.
- A film includes it with `<script src="tunables.js"></script>` before any script that builds the
  timeline or the scene (HyperFrames needs the timeline fully built before it is registered). A page
  puts it in `<head>`.
- Text is data, not markup: `data-tn-text` sets `textContent`, and the guide tells script authors to
  do the same.

## How each tool reads it

The entry points are the same for every tool: `tunable("id")` in script; `var(--tn-id)`,
`[data-tn-id]` and `data-tn-text` in CSS and HTML.

| Tool | Reads it as |
| --- | --- |
| GSAP | `tl.to(el, { duration: tunable("beat-02-duration"), ease: tunable("entrance-ease") })` |
| CSS, WAAPI | `transition-duration: var(--tn-beat-02-duration)`; `el.animate(k, { duration: tunable("beat-02-duration") * 1000 })` |
| canvas, SVG, code drawn from `t` | `tunable("accent")` inside the draw function |
| Anime.js, Three.js, Lottie, TypeGPU | same call where the tool takes options or uniforms |
| frontend pages and UI | CSS custom properties, `[data-tn-*]` selectors, `data-tn-text` |

This change tests GSAP, CSS custom properties, `data-tn-*` and a canvas page. The other rows use the
same entry points and are not exercised here.

## Findings

All are in the `tunables` step of `film check` and in `tunables check`. Each carries `fix`.

| Code | Severity | When |
| --- | --- | --- |
| `tunables-invalid` | error | the file breaks the schema or a rule above (duplicate id, control rule, bad colour, bad window, text too long) |
| `value-invalid` | error | a value has the wrong type, is out of range, or is not an option |
| `value-unknown` | error | `values` names an id that is not declared |
| `script-stale` | error | `tunables.js` is missing or differs from what `sync` would write |
| `script-not-included` | error | there are params and the entry page has no `<script src="tunables.js">` before its other scripts |
| `param-unread` | error | no project file reads the id and the param is not `dynamic` |
| `read-undeclared` | error | a project file calls `tunable("x")` with a literal id that is not declared |
| `render-older-than-values` | error | `film check` only: `tunables.json` or `tunables.js` is newer than the newest render |
| `param-no-visible-effect` | warning | `probe` only: every stable sampled frame is identical with the changed value |
| `probe-unstable` | warning | `probe` only: two loads with the same values differ at every sampled point (a clock, a video, an unpaused animation), so the param could not be judged |

A read is `tunable("id")` or `tunable('id')`, `--tn-id` (not followed by a name character),
`data-tn-text="id"`, or `data-tn-id` in a selector or `getAttribute`. Files scanned: `.html .js .mjs
.cjs .css .ts .tsx .jsx .vue .svelte` under the project root, skipping `node_modules`, `evidence`,
`renders`, `qa`, `.git`, `.design-pipeline`, `tunables.js` and `tunables.json`. The entry page is
`index.html` at the project root.

`render-older-than-values` uses file modification times, the ordering `newestRender` already uses.
It does not prove the render used the current values; it stops the case where a value changed and
nothing was rendered afterwards. A re-render already reopens the owner's review.

## Probe

`tunables probe --project-root <dir> [--param <id>]` loads the entry page from the preview server in
a headless browser. For each param it takes a screenshot with the effective value and one with a
changed value, at three times when the page registers a paused timeline (25%, 50% and 75% of the
param's `window`, or of the root `data-duration`; the timeline is seeked), and once after load
(300 ms settle, 1280x800) when it does not. Identical bytes at every sampled point report
`param-no-visible-effect` with the points tried.

The changed value: `range`, the bound farther from the current value; `color`, its RGB inverted;
`text`, the value with ` W` appended (cut to 500); `checkbox`, toggled; `select`, the next option
(wrapping). Before comparing, the page is loaded twice at the saved values (once per distinct time range,
shared by the params that sample it): a point that differs between those two loads moves by itself and
is dropped from the comparison; a param with no stable point is `probe-unstable`, not
`param-no-visible-effect`. Only a film waits for its timeline to register; a page is sampled once
after load. The change is applied as a draft in the preview server; the project's files are not written, and a
test compares their hashes before and after. Without a browser the command exits 1 with
`BROWSER_UNAVAILABLE` and the install command. `film check` does not run it.

A param that only changes sound, shows only in a hover or focus state, or shows between the sampled
moments gives a warning for a person to look at, not an error.

## Panel and preview server

`tunables panel --project-root <dir> [--port <n>] [--idle-minutes <n>]` runs in the foreground,
prints one URL and stops on Ctrl+C or after `--idle-minutes` (default 30) without a request. It does
not open a browser; the URL is printed so a person or the in-app browser can open it.

A page opened from `file://` cannot read or write the project, and frames of `file://` pages cannot
reach each other. A loopback server removes both limits and lets one mechanism serve the panel, the
preview and `probe`. The serving shape (`http.createServer` on `127.0.0.1`, port 0 by default, a MIME
map) is the one `tools/ff-tracking-hud/probe.cjs` already uses.

| Route | Does |
| --- | --- |
| `GET /<token>/` | the panel page, with the token and the file revision embedded |
| `GET /<token>/api/state` | `{ params, values, effective, revision, duration, timelineId, stale }` |
| `PUT /<token>/api/draft` | replaces the draft values (kept in memory, validated like `set`) |
| `POST /<token>/api/save` | writes the draft as `values` and re-runs `sync`; the body carries `revision` |
| `GET /<token>/preview/<path>` | a project file, read-only; `tunables.js` is generated from the draft |

**Safety**

- Binds `127.0.0.1` only. A request whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` is
  refused (DNS rebinding). Every route needs the random token (128 bits) as the first path segment,
  so another local page cannot call the API or read project files. The preview never lists a
  directory.
- A served file is resolved with `resolveInside` and `realpath`, must stay inside the project root,
  and must be a regular file. `..`, encoded separators, absolute paths and symlinks out of the root
  are refused, as are anything under `.git/` and `.env*` files.
- Only `tunables.json` and `tunables.js` are ever written, only by `save`, only after validation.
- Methods other than GET, PUT and POST are 405. Bodies over 64 KB are 413.

**Preview.** The panel embeds `/<token>/preview/index.html` in a frame of the same origin. When the
page registers `window.__timelines`, the panel seeks that timeline for the scrubber and "play" runs it
from the panel; otherwise the scrubber is hidden and the frame is the live page. The frame is
reloaded after a draft change (debounced 250 ms) so the page rebuilds from the new values. Three
buttons set the frame width to 375, 768 and 1280 px, which is how an owner checks a frontend page at
phone, tablet and desktop widths. The page reads `tunables.js` as it always does; the server decides
whether that request returns the saved values or the draft. The file on disk never reads the address
bar, so renders are unaffected. Sound and video clips are not played and the frame is not a render:
the panel says so in its footer.

**Controls.** One per param, grouped by `group`, labelled with `label`: `range` is a slider plus a
number box (`min`, `max`, `step`); `color` is a colour picker plus hex text; `text` is a text box
with a length counter; `checkbox` is a switch; `select` is a menu. Each shows its default and a reset
button. Focusing a control seeks the scrubber to the middle of the param's `window` when it has one.
An invalid entry is marked and not sent.

**Saving.** `Save` sends the draft with the `revision` (SHA-256 of `tunables.json` bytes) the panel
loaded. If the file changed since (an agent ran `set`, a person edited it), the server answers 409
`REVISION_CONFLICT` with the current state, writes nothing, and the panel shows a banner with two ways
out: **Keep my edits** (the unsaved edits stay and the next Save writes them on the file's latest
revision) or **Use the file's values** (the controls reload from the file's `values`). The panel keeps
the revision it loaded or last saved; a draft response never refreshes it. A state response carries
`stale` (the `render-older-than-values` finding, or null) when a render is older than the values, and
the panel shows its message and render command. The panel has no accept or reject control and renders
nothing.

**Tests.** The server is started on port 0 and driven over HTTP: routes, token, host check,
traversal, symlink, draft versus disk, save, conflict, invalid input, idle shutdown. One test drives
the page in a browser when one is available (change a colour control, read the frame's computed
colour, Save, read the file) and is skipped with the reason printed when not.

## Frontend pages and UI

A web project is any directory with an `index.html`. `tunables init`, `list`, `set`, `sync`, `check`,
`probe` and `panel` work on it without a film layout. There is no new `next` step: `workflow-web.md`
gains a short section saying when to expose params and how to read them, and its `build` row points at
it. The probe gate that `verify interaction` already runs is unchanged.

## Timing params and the storyboard

`storyboard.json` stays the plan of record. A timing param that moves a beat boundary makes the
captured `timeline.json` disagree with the storyboard, and the existing timeline gate fails. That is
the intended signal: keep the change inside the storyboard's tolerance, or edit the storyboard with
the same change. The guide says so and does not automate it.

## What authors expose

`workflow-film.md#build` and `workflow-web.md#build` gain: when the owner asks for something they can
keep editing, expose the caption and title text, the brand colours, each beat's or transition's
duration, the main ease and the main distances, radii or scales, one param each, with a `label` the
owner would recognise. Do not expose layout structure, asset paths or anything the owner did not ask
to change. Every exposed param must be read by the page and must show on screen; `check` and `probe`
enforce the first and test the second.

## Compatibility

- No migration. Projects without `tunables.json` get no new step and no new finding.
- `film scaffold --template default` adds three files and one `<script>` line. Tests that list the
  scaffold's files are updated in the same change. `motion-study` and `tracking-hud` are unchanged.
- `tunables init` adds the two files to an existing project and prints the one line to add to
  `index.html`; it does not edit the page.
- `playground-core.cjs` exports two more names and takes optional arguments; its tests are unchanged.
- Exit codes follow the repository: 0 passed, 2 gate failed (`check` and `probe` errors), 1 contract
  or usage error (bad value, unknown id, missing file, port in use). `panel` exits 0 on Ctrl+C or
  idle shutdown.

## Risks

- `param-unread` is a text search. A param read through a computed id needs `dynamic: true`; a literal
  id built by a template string is not found and is reported.
- `render-older-than-values` can be satisfied by touching the render. It guards against forgetting,
  not against forging.
- Colour params let an owner pick colours the contrast gate rejects. The gates run on the next render,
  which the stale-render finding forces.
- The panel is the first long-running process in this CLI. The idle timeout, loopback bind, token and
  `Host` check keep it from outliving its use or being reached by another local page; they are tested,
  not assumed.
- The preview frame has the panel's origin, so a script in the previewed project (including one loaded
  from a CDN) can read the token from its own address and call the panel API. What it can do is bounded:
  change validated values in `tunables.json` and `tunables.js`, nothing else. The panel is for a project
  whose scripts the owner already runs, as with their dev server.
- The preview rebuilds the page by reloading its frame, so a heavy page reloads on every change.
- A page that fetches a remote font or asset needs the network in the preview, as it does in a render.
- Values are fixed when `tunables.js` runs. A page that reads one after an async step still sees the
  same value, because the script is synchronous and runs first.
