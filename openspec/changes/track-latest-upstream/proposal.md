## Why

Owner decision (2026-11-04, #259): depend directly on the latest upstream for everything and stop
keeping old versions. On that day 28 of 55 pinned upstream repositories were behind HEAD and npm
dev dependencies lagged (`@fission-ai/openspec` 1.14.1 → 1.16.0, `hyperframes` 0.8.164 → 0.9.9).
Pins were scattered over importer constants (revision, Git tree, tree hash, file and byte counts),
vendor manifests, `component-source-catalog.json`, `companion-capabilities.json`,
`frontend-stack-registry.json`, `adapter-registry.json`, guide frontmatter, prose and tests. Moving
one source meant hand-editing a dozen files, and the policy ("an explicitly reviewed revision";
"never refresh a manifest by rehashing arbitrary source") made staying current a review project.

## What Changes

- `sources.lock.json` (repository root) is the single record of every upstream: id, repository,
  revision or release, commit time, review date and kind (`vendored`, `fetched-on-demand`,
  `adapted-reference`, `catalog-reference`, `npm`, `release`), plus the bundle content hash. Every
  derived pin must agree with it; `tests/sources-lock.test.cjs` checks that.
- Importers stop pinning a revision, tree, hash or inventory. They take the clean checkout they are
  given and keep their structural checks (required entry files, skill names, license text), so an
  upstream restructure fails the import instead of being imported quietly.
- `npm run sources:update [-- --only <id>]` resolves upstream HEAD (npm runtimes: the latest release
  and its tag), fetches it shallowly into a temporary directory as data, runs the source's existing
  importer, regenerates manifests, hashes, exhaustive package-resource listings and derived files,
  rewrites derived pins and updates the lock. A source whose upstream removed a file we cite, changed
  a license text we cite, or dropped a companion capability marker fails loudly and stays put.
- `npm run sources:check` keeps its offline integrity strictness and adds the lock agreement test;
  `-- --upstream` lists what is behind (warnings only).
- `.github/workflows/sources-update.yml` runs the update weekly and on demand, moves npm dev
  dependencies, runs specs and the full QA, and opens or refreshes one pull request on
  `chore/track-latest-upstream`. The owner merges.
- Policy text in `AGENTS.md`, `openspec/config.yaml`, `.github/CONTRIBUTING.md` and
  `docs/maintainers.md`: track upstream HEAD; integrity hashes are regenerated by the importer from a
  fresh checkout of the resolved HEAD; the bump PR with green tests is the review.
- First run: every source moved to its latest state except three held with follow-up issues
  (HyperFrames runtime #262, Astryx snapshot #263, `12-principles-of-animation` #264). Guides fixed
  where upstream changed: interface-discipline citations, good-css container and carousel notes,
  Cinetic script coverage, Impeccable command map and capability marker, React Bits license note.
- Supersedes `refresh-upstream-snapshots` (its refreshes are done here or held), which is removed.

## Capabilities

- `design-pipeline`: ADDED `Upstream sources track latest through one lock`, `Updating moves every
  source to upstream HEAD`, `Behind upstream is visible`, `A weekly pull request carries the bump`;
  MODIFIED the five source-snapshot requirements that required an explicitly reviewed revision.

## Reuse

- Existing importers, `scripts/git-tree-snapshot.cjs`, manifests, `sources:check` tests,
  `package-resources.json` and `capabilities:check` markers. New: the lock, its library, the updater,
  one generic importer for the five bundles that had none, and the MengTo projection script.
