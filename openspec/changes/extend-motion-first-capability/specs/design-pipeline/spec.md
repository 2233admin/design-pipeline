## ADDED Requirements

### Requirement: Motion-first reference stays project-owned

The pipeline SHALL expose a project-owned motion-first reference for non-trivial animation without installing or bundling the inspected upstream repository.

#### Scenario: Physical response is requested

- **WHEN** a target needs spring-like, inertia-like, trace, camera, or material response
- **THEN** routing SHALL require a named purpose, semantic subject, material surface, bounded parameters, interruption policy, reduced-motion substitute, and evidence plan.
- **AND** the implementation SHALL use the existing motion foundation and a selected semantic primitive rather than inventing a parallel runtime contract.

#### Scenario: Offline or seekable output is requested

- **WHEN** HyperFrames or another offline renderer samples the composition
- **THEN** authored time SHALL be the state authority.
- **AND** wall-clock time, unseeded randomness, network state, input history, or an uncontrolled requestAnimationFrame physics loop SHALL not determine the sampled output.

#### Scenario: External reference is consulted

- **WHEN** the inspected repository informs a design decision
- **THEN** the project artifact SHALL record `reference-only` and `codeCopied: false`.
- **AND** source code, assets, fonts, copy, cases, prompts, CLI shape, tests, and workflow derivatives SHALL not be copied.

#### Scenario: Capability registry is extended

- **WHEN** a new motion primitive is selected
- **THEN** it SHALL describe intent, channels, parameters, drivers, runtime capability, reduced-motion behavior, and provenance.
- **AND** it SHALL remain adapter-neutral and compatible with the existing motion foundation checker.
