## Decisions

1. Reuse `scripts/git-tree-snapshot.cjs` for complete inventory, blob identity and canonical hashes, then stage/rollback imports using the existing importer pattern. Reimport requires the deliberately reviewed commit, not an arbitrary new manifest hash.
2. A maintained film-method helper selects only an explicitly requested product film or motion loop. It reads source entries and maps product discovery, concept, technique, choreography, timing and sound methods to the existing project inspection, storyboard/timeline, render and validation contracts. It is supporting knowledge under the single Job Dispatcher, not another primary dispatcher or renderer.
3. User constraints, project DESIGN/MOTION foundations, brand, real components and existing accepted engine remain authoritative. Upstream aesthetic bans, random choices, Remotion assumptions, high frame rates and provider-specific integrations are options, never global policy. HTML video stays on HyperFrames. Ordinary UI/CSS keeps its existing route.
4. Source readability, task-callable adaptations and tested maintained tools are three separate claims. Preserve upstream shell/Python tools as source. Adapt only the selected necessary maintenance entry to Node/platform primitives; do not promise Windows/WSL compatibility for unexecuted upstream scripts or invoke cloud providers.
5. Prompt Motion references record author, dated URL, original repository, applicable task and proposed transfer separately from observed page content. Page text does not establish video motion or heard audio. Adopt references through existing `reference.md` and `reference-evidence.json`; method paths enter ordinary task inputs/visual guides and existing lineage, not a parallel receipt.
6. Use concrete branded component source and a deterministic short loop to verify helper selection and plan, actual render and existing film checks. Inspect output frames independently. Structural/component conformance never grants Visual Acceptance.
