# 组件评测底座：软件需求规格说明（SRS）

状态：第 2 阶段待审稿；本轮对话已确认范围与推进方式，规格正文尚未单独审阅；底座尚未实现。

来源：2026-10-06 本聊天。用户要求先对齐评测工具，能看到从派发到模型干活的过程，并让模型理解更细的任务；选择“关键视觉节点验收，其余自动”；随后确认只用珐琅徽章组件评测，并说明这几个模型有无限 token。现状依据见 [提示与执行复盘](badge-prompt-review.md)；历史结果见 [results.md](results.md)。本事项没有关联执行 issue。

## 问题

用户只能从现有页面看到最终徽章作品与汇总状态，难以判断模型拿到什么任务、实际执行了什么、卡在哪里，以及工具是否帮助它改进。现有派发一次要求完成整个徽章与动画，工具指导也以较大的动作组织，难以定位参考理解、几何、材质或执行环节的问题。

已核实：OMP 运行器已有逐行事件与错误日志，结束后汇总实际响应模型；现有页面未呈现执行时间线。仓库已有重建步骤和灰模、几何、最终证据校验，本次徽章派发没有按这些步骤展开。运行器仍有历史 12 分钟上限；现有 execution slices 表示文件范围与执行所有权，不能当作完整的美术任务卡。

## 方案

先建立单一珐琅徽章组件的本地评测底座：明确任务卡，关联真实执行事件与产物，在关键视觉节点等待用户验收，再根据反馈保留新的修改版本。工具版与直接制作版共用参考和任务目标，用已有运行、证据与评分机制判断这一个案例里的差距。

## 场景

1. 用户派发徽章制作，打开一个运行条目即可看到请求模型、实际响应模型、完整派发输入与当前小任务。（D1–D4）
2. 模型执行文件编辑或命令，用户在运行结束前看到实际动作、结果或错误，并能打开对应文件差异或已生成产物。（D3、D6）
3. 几何或材质节点完成，用户验收后继续；拒绝并给出反馈时，后续依赖步骤等待，修改记录保留原作与反馈。（D5、D6）
4. 组件运行检查通过但用户认为珐琅效果不好，工程通过和视觉拒绝同时存在，不能合成“已通过”。（D7）
5. 制作超过旧实验的 12 分钟或使用更多 token，新运行不因此自动淘汰；服务实际报错时如实显示，旧运行的时限失败不被改写。（D8）
6. 用户比较同模型的工具版与直接版，能确认输入与执行政策，并查看失败、反馈和改动；没有评分时保留未评分。（D9）

## 定下的事

### D1 评测范围

- 要求：第一版只以用户原片的珐琅徽章组件为评测案例，过程、阶段产物与最终效果都围绕它组织。
- 依据：用户先收窄为徽章，本轮再次确认“做个组件作为评测”。
- 例子：MiniMax、Grok、Qwen 的徽章记录可以进入此案例；历史前端与游戏 VFX 不进入当前派发。此次组件结果只支持本案例判断，不能推断其他组件或整个项目普遍进步。

### D2 模型领取的小任务

- 要求：每个任务卡有一个目标，并提供输入与依赖、允许修改范围、所需工具指导、交付物和验收条件；已完成产物作为下一任务的明确输入。
- 依据：用户要求拆细，使模型理解颗粒度；已认可上一轮的任务卡与徽章分阶段建议。
- 例子：蓝色釉面任务读取已固定的几何和参考裁图，交付固定视角图、参数变化与代码差异；不在这个任务内重新安排五层结构与整段动画。
- 模块与接口：派发模块向执行器提交任务卡与引用输入；工具指导按适用条件、输入、操作、产物、失败处理组织。任务卡与实际派发提示均需可追溯；具体存储字段见“未定”。

### D3 真实过程可见

- 要求：任务运行期间展示工具调用、开始与结束、读写文件、命令结果、错误及当前任务；模型给出的公开进度说明和工具执行事实分别显示。
- 依据：用户要求看到“模型在干什么、他做了什么”，并认可执行记录方案。
- 例子：文件写入事件只能证明该次写入完成，不能证明画质改善；模型说“完成”而检查失败时，两项记录都显示。历史只有最终源码时，只展示已有证据，不能伪造中间文件版本。
- 模块与接口：读取现有 OMP 日志中的公开执行事件，与运行／任务身份关联；流水线状态事件保持自身来源。页面不能等整个运行结束后才展示已收到的执行事实。公开界面不包含认证数据或模型内部思维内容。

### D4 模型归属

- 要求：每个任务与版本分别记录请求模型和实际响应模型，未收到响应时明确实际模型未知。
- 依据：用户此前要求写清模型；本轮认可任务卡显示请求与实际模型。
- 例子：请求 Grok 但只有上游错误时显示请求与错误，不填写成功作者；响应身份不匹配时保留事实，不把作品标成原请求模型成功。
- 模块与接口：使用现有本地模型选择及 OMP 响应元数据；历史 selector 是溯源数据，不作为硬编码产品默认值。

### D5 人工验收节点

- 要求：几何与材质等关键视觉节点等待用户验收，其他已具备条件的步骤自动推进；反馈必须关联当前产物版本。
- 依据：用户选择推进方式 1，并要求先做好底子。
- 例子：几何产物待审时，依赖已验收几何的后续任务保持等待；通过后释放这些任务；拒绝后保留意见并交给修改任务。一次验收不自动批准后续改变的产物。
- 模块与接口：关联既有阶段状态、产物摘要与用户决定；等待发生在任务边界。此要求不声称 OMP 已支持进程内暂停或恢复。

### D6 版本与产物关联

- 要求：保留参考、提示、工具版本、源码及产物身份，并将每次修改、检查与反馈关联到对应版本。
- 依据：此前逐版对照要求，以及本轮认可的版本与评测方案。
- 例子：用户认为某版釉面太暗，新版关联这条反馈及改动；旧截图、错误和评分继续可查，新截图不继承旧评分。
- 模块与接口：复用既有摘要、产物与收据关系；上游产物改变时按已有规则重算或失效下游证据。原始运行数据仍留在本地忽略目录。

### D7 工程与视觉分开

- 要求：运行、shader、控制等工程结果与用户的几何、材质、运动评价分别记录。
- 依据：仓库政策、用户人工打分要求，以及对当前所有效果不满意的明确反馈。
- 例子：shader 编译成功、用户视觉拒绝，是两项有效结果；未打数字分时保持空值。模型自述、自动门禁与文件写入均不能代替用户视觉认可。

### D8 Token 与耗时政策

- 要求：按用户提供的无限 token 条件，新底座不设置累计 token 淘汰线，不沿用旧实验统一 12 分钟制作淘汰线；token 与耗时用于过程记录。
- 依据：本轮用户明确说明“我们那几个模型是无限token”。此为用户给定的执行条件，未独立验证账户额度。
- 例子：新任务超过旧上限仍可继续；真实服务错误、用户停止与视觉未通过分别记录。历史 12 分钟运行的原始时限和失败结论继续保留，不按新政策回填成功。
- 模块与接口：执行器记录请求设置、实际使用量、耗时与终止原因；具体运行保护与超时设置见“未定”，不能把不存在的用量当作 0。

### D9 组件内的工具对照

- 要求：同模型工具版与直接版使用相同公共参考、任务目标、基础运行环境、执行政策和评审条件，差异显式记录。
- 依据：既有工具／直接对照要求，本轮确认继续以同一组件评测。
- 例子：两组都收到“蓝色釉面”任务，工具指导只提供给工具组；不同模型的差距、不同反馈后的修改或不同工具版本的迭代分别标识。用户看到模型身份的评分保持非盲评，不能报告盲评公平性通过。

## 测试决定

本轮只整理规格并校验文档，不启动新模型或重跑旧作品。已核实存在工程检查、模型身份汇总、摘要验证和评分导出的先例。后续验证需覆盖实际模型未知／不匹配、执行成功／失败、待验收／通过／拒绝、产物更新使旧证据失效，以及新运行／旧时限记录的区分；具体检查层和执行安排尚未批准，见“未定”。

## 不在范围

- 前端页面复刻与游戏 VFX 新案例：用户已停止，并再次确认只做组件案例。
- 本轮新徽章创作或额外模型连接实验：先做好评测底座，尚未进入新制作轮次。
- 自动视觉认可或据此宣称项目全面提升：由用户验收，本轮样本仅有一个组件。
- 并行的门禁、收据、目标解析器或策略摘要体系：遵循仓库既有契约与证据规则。

## 未定

- 任务卡、运行视图与公开事件投影的具体存储字段和读取接口：在后续设计或实施计划中明确，否则不能对外承诺稳定接口；功能输入输出已经由 D2–D6 限定。
- 执行器针对无事件、连接挂起等运行故障的保护方式与参数：没有确认值，不能复用旧总时限冒充新政策；不影响 D8 的 token 决定。
- 是否另出 SDD 与独立测试计划：待用户选择；未选择前不生成。规格文本待审，正式代码实现尚未批准。
