## ADDED Requirements

### Requirement: Video observation hands actual images to the applicable production skill

The existing reference action SHALL provide image-reading inputs and deliverable-specific guidance without claiming unobserved facts.

#### Scenario: A generated-film observation reaches the making capability

- GIVEN a bound video report with an unresolved window and a film replicate job
- WHEN the public next action dispatches reference study
- THEN the action includes that window's actual image inputs and the film direction and animation guides
- AND it retains the moving-reference study instead of replacing it with a coverage-only instruction
- AND the production handoff uses existing reference notes, storyboard fields and choreography without a new gate or receipt
- AND unknown poses, hidden layers and missing assets remain explicit rather than claiming automatic extraction or character replacement
- AND the code index locates source references while asset availability is verified against actual files
- AND jobs without an adopted reference continue planning from their brief or selected concept
- AND each selected window exposes its real PNG paths, hashes, and decoded times to the host image-reading tool
- AND the action preserves the deliverable-specific study instruction and names applicable packaged guides
- AND viewing a path or HTML index alone does not count as image perception
- AND sampling windows and pixel-change candidates are not called confirmed shots automatically

#### Scenario: The scaffold is not the reference film's storyboard

- GIVEN the exact shipped example storyboard and a replicate film job
- WHEN next chooses the plan action, even if the example passed the structural storyboard gate
- THEN it requests adapting the example to the inspected reference and existing production notes before building
- AND a changed reference note reopens the existing plan check
- AND neither template detection nor structural validation grants semantic or visual acceptance

#### Scenario: Film observations become production notes

- GIVEN inspected source passages for generated film reconstruction
- WHEN the agent records the existing `reference.md`
- THEN it separates observed facts from proposed layers, motion responsibility, key poses, available assets, and asset gaps

### Requirement: Video references expose decoded temporal evidence before reconstruction

The packaged reference entry SHALL prepare source-bound temporal video evidence and observation tools without claiming semantic or visual acceptance.

#### Scenario: Variable rate video and short changes

- GIVEN a supplied video with nonuniform frame timestamps
- WHEN the reference analyzer prepares overview and ordered windows
- THEN frame timestamps come from decoded PTS rather than requested seek time or index divided by nominal fps
- AND each window exposes ordered frames and their exact times
- AND sampling limits and unobserved intervals are explicit, with local denser sampling available
- AND the report binds original media bytes, dimensions, and duration to decoded presentation timestamps and source frame indices
- AND sparse overview frames remain distinct from ordered temporal samples
- AND bounded windows, candidate changes, interval resampling, and an observation template expose named targets, properties, start/end states, evidence, and uncertainty
- AND mechanical preparation does not claim semantic or visual acceptance

#### Scenario: Prepared frames have not been interpreted

- GIVEN a prepared video report without model observations for its windows
- WHEN the existing reference evidence check consumes the report
- THEN observation remains pending and names the missing windows
- AND source, report or frame drift cannot pass as current evidence
- AND technical validation does not certify object semantics, easing, camera reconstruction or visual acceptance

#### Scenario: Unknown entries and whole-clip motion cannot substitute for local observation

- GIVEN observations marked unknown or inferred, or a whole-clip motion claim citing only distant endpoints
- WHEN the existing reference checker measures observation coverage
- THEN only an observed claim with evidence inside the particular window satisfies that window
- AND a motion claim needs two distinct presentation times inside every window it covers
- AND the checker returns the unresolved windows with their source frames and an executable local resampling action
- AND remaining uncertainty is retained without claiming semantic acceptance

#### Scenario: Short change candidates survive bounded sampling

- GIVEN a high frame rate source and candidate pixel changes between the overview samples
- WHEN the analyzer prepares the bounded evidence
- THEN candidate context uses time-spaced source frames rather than only adjacent source indices
- AND complete candidate sequences and overall endpoints are retained before filling the remaining frame budget
- AND an omitted candidate sequence is named for local resampling instead of appearing fully inspected
- AND the public entry exposes the existing bounded frame budget through `--max-frames` (2–400), with concrete recovery even when window observations were already recorded
- AND a local-only report still offers the full-source preparation needed by the existing whole-reference workflow

#### Scenario: Existing static geometry comparison uses a video frame

- GIVEN a video report retaining original media and temporal evidence
- WHEN an agent selects a real sampled PNG for the existing graybox or calibration comparison
- THEN the image source must match a frame path, digest and dimensions from the bound report
- AND temporal observation remains required for the original video
- AND image selection does not replace the original video provenance or grant fidelity for other times

### Requirement: Project analysis exposes implementation evidence rather than filenames alone

The packaged project inspection entry SHALL provide bounded, source-backed project evidence through existing path and artifact helpers.

#### Scenario: Existing animated frontend project

- GIVEN a project containing HTML or framework entrypoints, shaders and animation code
- WHEN project inspection is requested
- THEN it returns source-backed entry and dependency relationships and implementation candidates
- AND it offers concrete next source reads instead of silently selecting a framework or renderer
- AND it does not execute project scripts or imported source content

#### Scenario: Partial or scoped repository

- GIVEN excluded dependencies, ignored/private files, a narrow scope or exhausted scan budget
- WHEN project inspection completes
- THEN the report identifies its read scope, exclusions, truncation and unresolved relationships
- AND a partial heuristic index is not described as a complete understanding of the repository

#### Scenario: An agent searches for a specific implementation

- GIVEN an inspection query naming an object, material or source symbol
- WHEN project inspection completes
- THEN literal source matches retain path, line, digest and matched terms
- AND the existing resolved import graph connects entrypoints to matching files where possible, retaining source evidence for each edge
- AND absent matches, unresolved relationships and exhausted search budgets are explicit
- AND lexical matches and import paths are not described as semantic recognition or runtime call traces
- AND writing an inspection report requires a new output path, preserving source files outside the inspected scope as well as earlier reports
- AND bounded inspection covers manifests, entrypoints, imports, components, renderer, material/shader, animation, tokens, and build/test commands
- AND each finding retains source path, line, and byte digest while using existing contained-path and artifact-metadata helpers
- AND no parallel target resolver, snapshot identity, policy digest, receipt schema, or acceptance gate is created
- AND unknown aliases, dynamic or missing imports, and budget exclusions remain explicit
