## 工作模式

采用 TDD，在一个最小端到端工作中交付：用户打开本地评测台，能从旧徽章的派发输入追溯到工具执行和产物，并能为新的徽章制作选择模型、领取小任务、查看执行、验收或反馈。

工作分解建议：本次是同一案例、同一运行服务和状态关系，建议作为一个可整体验收的工作，不另拆外部子工作项；第 3 阶段采用这项建议须随本计划确认。依次完成历史过程可见、任务执行、关键节点验收，执行者为当前 Codex；当前没有关联原生 issue。本轮仅准备已有关联 OpenSpec 的方案，不值得开票；正式执行前按宿主 Multica 规则承接或登记，不能另开 GitHub 工作票。

### 任务与记录接口

- 任务卡采用已有 `design-pipeline.design-plan.v1` 的 phase 身份、依赖、输入与输出关系；任务目标、参考、允许修改范围、指导内容与验收说明存入评测扩展字段。通过现有 `validatePlan` 检查依赖，复用产物元数据和下游失效计算，不另建门禁或收据格式。
- 运行状态使用已有 `design-pipeline.state.v2`、`event.v2` 及状态／事件事务工具，评测任务、模型归属与人工决定置于 `extensions.componentEval`；保留 OMP 原始事件的单独来源，不将其伪装成流水线原生事件。
- OMP 事件仅投影公开进度、工具调用和结果、模型响应元数据、错误及用量；按工具调用 ID 关联开始与结束，增量读取日志。历史缺少事件时间或文件中间版本时明确缺失；新运行记录接收时间，并保存任务前后文件快照供差异查看。
- 关键视觉产物登记现有 artifact 元数据，反馈与评分携带任务身份及产物摘要。验收前重新核对实际摘要；产物漂移时失效相关决定与下游证据。工程结果与视觉决定分别保存。
- 徽章任务按参考拆解、灰模／结构、三类材质、合成和动作组织；每次模型收到当前小任务、对应指导和已经允许使用的上游产物，不再收到一次完成全部工作的要求。工具组使用真实路由返回的相关指导，直接组保留相同目标和参考；不再固定跳到 `web/quick/freeform`。

### 本地服务与执行接口

- 本地服务只绑定 `127.0.0.1`，使用独立端口；提供运行列表／状态、任务详情与派发输入、带游标的公开事件读取，以及开始、产物验收／反馈、停止操作。写操作校验本地会话、目标运行和当前产物摘要；文件访问校验真实路径范围，认证配置与原始私有事件不作为可浏览静态资源。
- 用户选择显式模型和工具／直接条件后创建新运行；配置复用现有 OMP 接入。沿用逐任务 `--mode json` 的子进程方式，去掉旧 `--max-time=12m` 和 810 秒总运行终止器，不设置累计 token 淘汰线。真实退出、上游失败和用户停止保留各自原因。
- 保持自动回退关闭；若仍记录到不同实际模型或回退事件，则显示归属问题并停止自动推进，不能按请求模型记成功。无事件或连接异常时展示最后收到事件和已有故障信息，用户可以停止；第一版不自动重派任务、不自动切模型或自行设置新的总时限。
- 任务结束后登记已存在的产物与外部工程证据。没有产物或工程证据时明确缺失，不仅凭退出码或模型自述宣布就绪。通过人工验收才释放依赖该产物认可的任务，其他符合条件的小任务自动执行。
- 用户拒绝并提交反馈时，保留被拒版本，建立关联该产物与反馈的新修改尝试；旧尝试不重标成功。修正版再次登记产物并等待同一视觉节点验收，下游等待期间不能越过节点。
- 服务重启不自动恢复或重新派发先前进程；先展示落盘状态和日志，对无法确认的活跃状态标明未核实。停止操作只针对本服务持有的子进程。

## 测试挂哪

- 每片红绿检查使用 `node --test tests/component-eval.test.cjs`，显式指定这个文件，不做裸测试发现。检查接缝是 OMP 逐行流、状态／事件一致性、真实文件摘要及本地 HTTP 操作。
- 同一个新测试文件覆盖：分块／半行 JSON 与工具开始／结束；实际模型未知／匹配／不匹配；公开事件过滤；成功／错误／用户停止；几何待验收／通过／拒绝及摘要漂移；路径越界；新运行无旧总时限与旧时限记录保留。用受控子进程提供事件，不能写模拟用户评分到真实作品。
- 基本链路完成后，在实际本地页面检查一条旧徽章日志能显示模型、派发提示、真实工具动作、最终产物和旧失败。再以临时运行数据检查等待验收和反馈界面；不据此宣称真实新制作或美术通过。
- 修改完成后运行一次 `node scripts/qa.cjs`、`openspec validate evaluate-design-model-progress --strict --no-interactive` 和 `git diff --check`；没有额外 TypeScript 类型检查。后续只有新改动、失败或未解决问题才重复相应检查。
- 第一版底座交付不额外请求模型连接探测或重跑六组作品。新制作由用户在评测台选择任务启动，首个关键视觉节点仍由用户验收；实际供应商执行行为与画质在那时分别取得证据。

## 不动什么

原片、旧提示和冻结工具快照、旧模型源码与 MP4、旧评分与时限、现有 `47831` 预览服务、`skill/` 既有门禁／收据／路由／模型默认配置及无关未提交修改。此计划不含提交、推送、PR、合入、安装或公开发布。
