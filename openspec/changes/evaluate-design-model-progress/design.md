### 实际底座接口与边界

本地 Node 标准库 HTTP 服务独占一个数据目录并绑定 `127.0.0.1`，同一时刻只派发一个任务。`GET /api/bootstrap` 提供当前本地会话和从历史矩阵读取的模型选择，`/api/runs`、`/api/detail`、`/api/events?cursor=`、`/api/file` 提供运行、提示、公开事件与源码。`POST /api/create`、`/api/start`、`/api/stop`、`/api/review` 校验 Origin、Host 和本地会话；审阅再校验任务、尝试和产物摘要。模型无产品默认值，启动命令显式提供 OMP、配置、工具快照、基础依赖和已安装的浏览器路径。

七个顺序任务为参考拆解、灰模结构、蓝釉、银色、虹彩镶片、材质合成、动作。几何、合成和动作等待人工决定。每次尝试保存自己的提示、输入摘要、实际响应身份、用量、时间、上游尝试、工程结果和人工意见。只有取得该次任务的完整响应身份、要求文件和独立检查才允许进入待审；退出码或上一任务的模型身份不替代这些证据。

状态与流水线摘要事件采用 `design-pipeline.state.v2`／`event.v2`，任务身份与依赖复用 `design-plan.v1`，检查复用 artifact 元数据、摘要校验和 `invalidateDownstream`。评测扩展在 `extensions.componentEval`；原始 OMP 日志保持单独来源。事件投影去除内部思维内容和认证字段，只显示公开工具调用、结果、模型身份与公开说明。历史无接收时间或中间版本的地方保持缺失。

每个新运行复制固定参考，公共输入摘要包含参考内容、任务目标、基础库版本和执行政策；模型、条件和工具内容摘要另计。工具版本摘要按排序后的相对文件名／SHA-256 记录计算，不能直接与历史驱动的另一种目录摘要算法等同。工具在任务开始和结束校验；直接条件不获得工具链接。基础依赖沿用已安装的只读链接，任务前后保存组件源文件快照。独立 Chrome 检查加载、shader 编译／链接、固定时间与两个角度；动作另检查真实播放推进。截图是工程证据，未做画面相似度评分。

拒绝保留被拒版本、评价和反馈，再复制源文件进入新尝试；通过只认可当前摘要。当前产物或其上游漂移时，相关产物及下游证据标记 stale，既有意见和评分保留但有效性置 false；等待任务不放行。停止只操作本服务拥有的子进程。重启读取落盘状态，对先前活跃状态标未核实，不自动重派。

运行与快照写入忽略目录 `model-eval/component-workbench/`，新原始事件和 stderr 写入预览根目录之外的 `.design-pipeline/component-eval-private/`。页面以 1.5 秒轮询读取已经投影的事件，文件范围校验真实路径且不公开认证配置。允许修改范围由提示和工具路径检查约束，这不是操作系统级沙箱；bash 的任意外部访问未被完全拦截。第一版的数据目录独占和事件顺序扫描适用于一个本地案例，尚未支持并行写入。

本轮以受控子进程和隔离真实浏览器验证底座，不发真实供应商请求；模型额度、实际供应商行为及新徽章画质留给用户启动后取得证据。当前启动服务指向旧 V3 快照，换新工具须显式配置并创建新的运行，不能覆盖既有版本。

## 复现并修正的工具问题

查询“制作游戏法术 VFX 效果，蓄力、冲击波、火花和消散，GPU shader，可重播和调整强度”原先返回低置信度 `product-design` / prism，而非已有 graphics-runtime。原因是 job registry 只列了库名与“粒子”，没有 VFX、shader、GLSL / WGSL、游戏特效词汇。

在同一 catalog 条目补足词汇；dispatcher、kernel、契约和收据不变。回归覆盖中文游戏特效、英文 VFX、GLSL / WGSL，并确认普通设置表单仍走产品 UI、明确产品影片仍走影片。修复后再冻结工具快照，模型无需替工具猜库名才能找到相应能力。

第二处缺口由 MiniMax 工具 VFX 组实际复现：Three.js 为 native，但没有 lifecycle，导致 toolchain resolve 恒被阻塞。沿用既有 Reflex/XY lifecycle 形状，为 Three.js 添加 target-project probe / plan / invoke / verify。probe 只读取目标的 package.json 与 node_modules/three，要求声明版本与安装版本精确一致，并有项目自有 scripts.dev；不会全局找包、安装或启动服务。invoke 使用 `npm run dev`；现有启动方式可通过该脚本调用。没有这个脚本就保留 blocked。verify 仍使用 toolchain-receipt.v1，要求真实 scene / screenshot / performance 证据；包可导入不是 shader 编译或画质接受。

该修复是在实验快照冻结之后发现的，属于历史工具迭代 V4。Qwen 与已有作品继续使用相同 V3 快照，明确不声称测过 V4 的创作效果。

## 好用的制作流程

| 阶段 | 要做的工作 | 产物与通过条件 | 遇到问题如何迭代 |
| --- | --- | --- | --- |
| 1. 参考研究 | 看运动和正面 / 侧面 / 拆层；分开记录几何、珐琅、金属、嵌片、照明 | `reference.md`、带时间的样帧与明确材质要求 | 修正观察，避免将“有颜色”误当“有釉面” |
| 2. 路线与分镜 | 为实体厚度、倒角、clearcoat、起伏和视角色选择能实现的路线 | 工具组填写 `storyboard.json.rendering`；直接组写自己的计划 | 所选路线缺能力时更换路线，保留原片要求 |
| 3. 最小材质样片 | 先做一块实体徽章和固定时间的两个角度 | 编译正常、釉面有移动高光、纹理固定在物体上 | 先调材质与照明，再加整段动画 |
| 4. 几何与运动 | 五层保持同一主体；每层厚度、掐丝、嵌片和标签；按参考拆合转动 | 可定位到指定时间，反向定位一致，动作不会冻结 | 每次只修改一个明显偏差并保留上一版 |
| 5. 实际导出 | 同一浏览器 / 编码规格生成完整 935 帧 | MP4 可解码、尺寸 / 帧率 / 长度 / 无声符合要求 | 运行故障归入工程结果，不伪装成美术评分 |
| 6. 对照评审 | 同时刻与原片比较，每行同模型、左直接 / 右工具，模型直接显示 | 记录技术检查、人工视觉评分、用户意见 | 以用户指出的差距作为下版需求；门禁不代表接受 |
| 7. 归档迭代 | 保留输入、提示、工具快照、实际模型、源码和输出摘要 | 版本条目能复跑、能说明改了什么及为何更好 | 未验收仍保持未验收，未执行保持未执行 |

工具组沿现有 `reference → plan → build → check → done`；直接组自行制作。两组共享基本渲染接口，以便使用同一个外部导出器；此接口不是 design-pipeline 的美术方案。
